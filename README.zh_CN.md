# Mindustry 启动器 —— Windows 上的多版本管理器

官方的 Mindustry（像素工厂）桌面版只给 jar：想留几个版本，得自己建目录、记住哪个文件是哪个，
每次手敲 `java -jar`。更麻烦的是**所有版本共用同一份数据** —— `%APPDATA%\Mindustry` 里的
存档 / 地图 / 蓝图 / 模组 / 设置，在哪个版本里玩都压在同一个地方；想留两套存档，只能手动搬目录。

这个启动器把这两件事拆开：版本并排留着、点一下就启动；每个**存档分类**是一整套独立的数据目录；
退出后按条件自动备份。tkinter 界面，**Java 已经打包在里面** —— 不用装 Python，也不用单独装 Java。

## 它解决什么

| 自己管 jar + 官方数据目录 | 用这个启动器 |
|---|---|
| 几个版本并存要自己建目录、自己记哪个 jar 是哪个，每次手敲 `java -jar`，路径带空格还得加引号 | 版本列表一行一个，选中点「启动游戏」；窗口一打开就在后台把文件拼好，点下去不用等 |
| 所有版本共用 `%APPDATA%\Mindustry` 那一份数据，切版本 = 把旧进度顶掉 | **存档分类**：一个分类一整套数据目录（存档 / 地图 / 蓝图 / 模组 / 设置），启动前切一下，互不覆盖 |
| 多留一个版本就多占一整套体积（一个版本 110 MB 左右） | 版本文件按内容拆开、**相同的只存一份**；多装一个版本只多出真正不同的那部分 |
| 备份靠自己把数据目录整个复制一遍，过几天就分不清哪份是哪份 | 退出后**自动备份**（默认玩满 20 分钟才备、留 20 份），可加备注、可一键恢复；备份同样去重，多留几份不成倍占地方 |
| 更新得自己去 GitHub 页面翻 release、挑文件，网络一抖就断在半路 | 「检查更新」按一张**来源表**下载（内置 Mindustry / MindustryX，可自己加），带镜像、测速和**断点续传** |
| 机器上得先有 Java，版本不对还起不来 | **内置 JRE**；想用自己那份 JDK 也行 —— 填的路径 → 旁边的 `jre\` → 系统 `JAVA_HOME` / `PATH` 逐层兜底 |
| 出了问题只有游戏那份日志，还写在 `%APPDATA%` 里，换了分类就找不着 | 游戏输出被捕获下来，按分类留一份；日志窗口分「启动器日志 / 游戏输出」两段看 |
| 想从脚本、批处理或快捷方式直接进游戏，总得先点开启动器 | `--launch "版本名"` **零界面**直进；`--export` 还能把某个版本拼成能带走的 jar |
| 删掉的存档、旧日志找不回来 | 删除走**回收站**（设置里可以改成彻底删除） |
| 启动器自己有新版，得手动下来重装一遍 | 后台下好，等关掉时换上；**只替换程序文件**，不碰版本、备份、设置 |

**它是怎么做到的**：把每个版本拆成许多小文件块存起来（相同的块只留一份），启动前再拼成一个
运行时 jar；存档隔离靠启动时把游戏的**数据目录**指向那个分类的目录。游戏本体、存档格式、
模组生态都没被改动 —— 启动器只负责拼文件、起进程、管备份。

## 怎么用

1. **下载** —— 从 [Releases](../../releases/latest) 拿发布包，解压到一个**有写权限**的位置
   （别放 `C:\Program Files`、桌面这类地方），双击 `Mindustry启动器.exe`。包内
   `使用说明.txt` 是步骤版，中英对照（上半中文、下半英文）。

2. **先把一个版本弄进来** —— 首次打开本地还没有版本，二选一：
   - 点「**检查更新**」下载一个（走 GitHub；慢的话在设置里填镜像）；
   - 点「**管理版本 → 导入版本**」选别人给的 `desktop.jar`，填一下版本类型和版本号。

3. **开玩** —— 在列表里选中它，点「**启动游戏**」。想再要一套互不干扰的存档：主界面
   「**管理存档**」新建一个分类 → 切过去 → 再启动，游戏读到的就是另一份数据目录。

界面**跟随系统语言**：中文系统上是简体中文，其它显示英文。设置里可以覆盖，也能自己放一份
`lang\zh_CN.json` 改词（见〔不用重新打包就能改的东西〕）。

## 能做什么

### 版本

- 列表一行一个版本（`Mindustry v146`、`BE v146` 这样），选中点「启动游戏」
- 「管理版本」里：导入本地 jar（选 `desktop.jar`）、重命名版本号、删除
- **相同文件只存一份**：第二个版本通常只多出真正不同的那部分，不是又占一整套
- **启动预热**：窗口一打开就在后台把选中版本拼成运行时 jar，点启动时不用干等
- 游戏在跑时，改版本 / 切分类 / 开设置一律拒绝 —— 免得动到正在读的文件

### 存档分类

- 一个分类 = 一整套数据目录：存档 / 地图 / 蓝图 / 模组 / 设置
- 主界面顶部下拉框切换；「管理存档」里新建、改名、删除、打开目录
- 每个分类单独设：数据目录、自动备份开关、最小备份时间（1~60 分钟）、最大备份数量（1~50 份）
- ⚠️ 改数据目录**只改「以后用哪个目录」**，原有存档不会被搬走 —— 要搬得自己搬
- ⚠️ 切分类只影响**下一次启动**；游戏在跑时不让切

### 备份与恢复

- 「立即备份」手动备一份；退出游戏后按当时分类的策略自动备份（默认：玩满 20 分钟、留 20 份）
- 备份按分类隔离，列表里能加 / 改备注，一眼看出这是哪一局
- 恢复前先确认（会覆盖该分类当前的存档）；游戏在跑时拒绝恢复
- 备份按内容去重，多份备份不成倍占地方；超出份数从最旧的开始删
- 超出份数的自动清理、版本库里没人再用的文件块是硬删 —— 「删除走回收站」只保护存档目录、
  旧日志这类用户文件

### 检查更新与镜像

- 「从哪儿下游戏版本」是**一张表**：内置 Mindustry、MindustryX 两个来源；`config.json` 的
  `version_sources` 可以往里加，`type` 跟内置的重名就是**覆盖**它（比如换成自己的镜像仓库）
- 只挑对应的文件（`asset_pattern` 正则），正式版 / 预发布可以筛
- 镜像留空 = 直连 GitHub；下拉框有几个常用镜像，也能自己敲地址；某个源拉不动会自动换下一个
- **测速**：对每个候选（含直连）真下一小段、按速度排序（轮数 1~3），「用最快的」一键填回设置
- **断点续传**：断了（网络抖、关掉启动器、换镜像）下次接着已经下好的部分继续，不从头来
- 下完先核对大小 / 校验值，再装进版本库

### 命令行

界面能做的事，命令行里也能做一份 —— 适合写进脚本，或者干脆不想开界面：

| 开关 | 做什么 |
|---|---|
| （不加参数） | 打开启动器界面 |
| `--launch <版本>` | 直接启动某个版本，**全程不显示启动器窗口**；游戏退出后启动器自己收工 |
| `--list` | 列出本机已有版本（不启动任何东西，连界面模块都不加载） |
| `--list-backups` | 按分类列出存档备份（时间戳 + 备注） |
| `--get [键]` | 看设置；不写键就全列出来，打出来的写法能直接抄给 `--set` |
| `--set 键=值 …` | 改设置（只写 `config.json`，下次启动生效；能一次给好几项） |
| `--export <版本>` | 把版本拼成能直接 `java -jar` 的 jar，可加 `--out` |
| `--export-backup <分类> [时间戳]` | 把一份备份拼成 zip（省略时间戳 = 最新那个），可加 `--out` |
| `--help` | 用法、退出码、几个注意点 |

```bat
"Mindustry启动器.exe" --launch "Mindustry v146"
"Mindustry启动器.exe" --export "Mindustry v146" --out D:\分享\
"Mindustry启动器.exe" --set language=en_US auto_update=false
```

- **一次只做一件事**，优先级：`--help` → `--list` → `--list-backups` → `--get` → `--set`
  → `--export` → `--export-backup` → `--launch`（只读的排前面；导出排在启动前）
- **零界面**：屏幕上不会冒出窗口，进度和结果都写在你敲命令的那个控制台里；名字写错、参数只写了
  一半时**什么都不会启动**，控制台里说清原因
- ⚠️ cmd 对窗口程序**不等待** —— 提示符立刻就回来了，还排在程序输出前面。以**最后一行**
  `启动器已退出（退出码 N）` 为准；想让命令跑完才回到提示符，写进 `.bat` 或加 `start /wait`
- 退出码：`0` 正常（游戏玩完退出也算）· `1` 启动器崩了 · `2` 参数写坏 · `3` 没有这个版本或备份 ·
  `4` 版本在但没拉起来 · `5` 导出失败 · `6` 改配置失败（启动器正开着 / 写不进去）
- 导出的文件同名时不覆盖，自动变成 `..._2.jar`；导出的 jar 是压缩过的（约 120 MB → 87 MB），
  保留原版 `Main-Class`，拿到就能用

### Java 与启动参数

- 双击就能跑：`jre\` 已经随包带上
- Java 路径填 JRE 或 JDK 的**根目录**（里面要有 `bin\java.exe`）；只写 `jre` 表示旁边那个；
  旁边有「检测」按钮可以找一个
- 兜底顺序：设置里填的 → 旁边的 `jre\` → 系统 `JAVA_HOME` / `PATH` → 都没有才报错。
  找到的系统 Java **只用于这一次**，不会悄悄写进设置
- 「额外 JVM 参数」加在 `-cp` 之前（如 `-Xmx4G`）；「额外游戏参数」加在主类之后，一般用不到
- 含空格的整项用英文双引号包住：`-Dfoo="bar baz"`

### 日志

- 游戏输出实时显示，退出后还能看；`logs\` 里每次启动留一份（设置里可以关掉）
- 日志窗口分段：**游戏输出** / **启动器日志**；能复制、能打开所在文件夹
- 保留份数 1~200，超出从最旧的开始丢
- 启动器自己的运行日志是 `launcher.log` —— 出问题先看这个

### 数据放在哪

全部在 exe 旁边，整个文件夹拷走就能一起带走：

```
versions\       游戏版本（相同文件只存一份）
Backups\        存档备份（按分类存放，同样去重）
logs\           游戏输出日志（每次启动一份）
runtime\        游戏进程的工作目录（游戏自己往里写缓存，不用管）
extensions\     自己写的扩展（可选，没有这个目录也不影响）
lang\           自己覆盖的界面文案（可选）
config.json     你的设置
launcher.log    启动器自己的运行日志
```

### 值得知道的几个设置

- **界面语言** —— `跟随系统`（默认）、`简体中文`、`English`；改完整个界面立刻换过来
- **启动器更新** —— `自动`（默认）后台悄悄下好，关掉时换上；`只提示` 只告诉你有新版；`停用` 完全关掉
- **GitHub 镜像** —— 留空 = 直连；旁边「测速」对每个候选真下一小段、按速度排序，
  「用最快的」一键填回。顺序不代表你这里的速度，值得先测一次
- **测速轮数** —— 1~3（默认 3），越多排名越稳也越等得久；填范围外的值会当场提示，不夹取
- **使用 GitHub CLI 认证** —— 默认关闭。本机装了 `gh` 并登录过的话勾上：API 额度从 60 次/时
  提到 5000 次/时。令牌只放内存、不写文件，镜像站和自定义来源收不到
- **删除文件时直接彻底删除** —— 默认关闭，所以删除走回收站；打开之后真找不回来
- **启动时隐藏窗口 / 游戏退出后自动关闭** —— 想要「点一下只剩游戏」的观感就开这两个

⚠️ 改完要点「保存并返回」才会生效。

### 不用重新打包就能改的东西

往 exe 旁边加点东西、或者手改 `config.json`，重启即可 —— 不用重新打包，也不用会编程。

- **界面文字 / 加一门语言** —— 新建 `lang\` 文件夹，放一份与内置**同名**的 JSON
  （`zh_CN.json` / `en_US.json`），**外面那份优先**。改坏了最坏是某几句显示成键名
  （比如 `settings.save_return`），删掉外面那份就恢复原样
- **多加几个「从哪儿下版本」的来源** —— `version_sources` 数组，只有 `type` 和 `api_url`
  必填；`asset_pattern` / `prerelease` / `use_mirror` / `sort_rank` 可不写。写坏了那一项会被
  丢掉并记一条日志，不影响其它配置。字段含义见 `launcher/sources.py`
- **镜像下拉框的几个候选** —— `github_mirror_presets` 数组，写进去就出现在设置页的下拉框里
- **自己加一点功能** —— 在数据根下建 `extensions\`，往里放 `.py`（每个要有 `register(api)`），
  启动时自动载入。四个钩子：`on_config_loaded` / `on_versions_refreshed` / `on_before_launch` /
  `on_game_exited`

  ```python
  # extensions\我的统计.py
  def register(api):
      api.on("on_game_exited", lambda **kw: print(kw["version_name"], kw["playtime_minutes"]))
  ```

  ⚠️ 扩展跟启动器**同权限**运行，只放自己写的或信得过的；怀疑是扩展搞的鬼，设 `MDT_NO_EXTENSIONS=1`
  就全部停用

⚠️ 手改 `config.json` 之前先**关掉启动器** —— 它退出时会把整个文件重写一遍。改坏了不用怕：
认不出的键原样保留、写坏的值退回默认并在 `launcher.log` 里点名是哪个键，不会让配置整个作废。

## 现在还没有的

- **macOS / Linux**：只发布 Windows 版（exe + 随包的 Windows JRE）
- **命令行只到「启动 / 查看 / 导出 / 改设置」**：没有 `--version`；`--launch` 用的是**当前**
  存档分类，不能临时指定另一个
- **模组 / 地图 / 蓝图没有专门界面**：隔离是按整个数据目录做的，这三样跟着分类走，但列表、
  导入导出、缺件分析这些桌面版不做 —— 游戏里本来就能管
- **扩展没有分发渠道**：`extensions\` 里放的是本地 `.py`，得自己写或别人直接发给你

## 不打算做的

- **打包或重新分发游戏本体**：版权归各自作者，版本一律从官方发布页（或你指定的来源）下载
- **改游戏本体**：不注入、不打补丁、不改动游戏内容；只把官方文件原样拼成能运行的 jar 再启动
- **多线程下载**：单线程够用，力气花在断点续传和换源上更值

## 注意

- **杀毒软件可能误报**（PyInstaller 打包的 exe 挺常见），信任一下即可
- 升级启动器**只替换程序文件**（exe 与 `_internal\`），不碰版本、备份、设置、扩展，也不动 `jre\`
- 「检查更新」一直失败，多半是连不上 GitHub：换镜像，或设环境变量 `MDT_SELFUPDATE_API`
  指向你能用起来的代理
- 出问题时把 `launcher.log` 一起发出来（必要时加上 `logs\` 里的游戏输出），每一步它都记着
