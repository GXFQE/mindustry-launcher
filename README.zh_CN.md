# Mindustry 启动器

**简体中文** · [English](README.md)

同时管理多个 Mindustry 版本、每个版本各用一套互不干扰的存档、自动备份。
tkinter 界面，**内置 Java** —— 不需要装 Python，也不需要单独装 Java。

---

## 下载使用

从 [Releases](../../releases/latest) 拿发布包，解压到一个**有写权限**的位置
（别放 `C:\Program Files`、桌面这类地方），双击 `Mindustry启动器.exe`。

首次打开时本地还没有游戏版本：点「检查更新」下载一个，然后在列表里选中它，
点「启动游戏」。

包内另有一份 `使用说明.txt`，内容与这份 README 一致，并且是**中英对照**的
（上半中文、下半英文）—— 界面切到 English 的用户看后半份就行。

## 主要功能

- **多版本并存** —— 相同文件只存一份，所以多装一个版本不会多占一整套的体积。
- **版本管理** —— 别人给的本地 jar 包可以直接导入（选 `desktop.jar`）；已有版本可以
  重命名、删除。都在「管理版本」里。
- **存档分类** —— 每个分类使用**完全不同**的游戏数据目录。切换分类再启动，
  游戏读到的就是另一套存档。每个分类可以单独设置数据目录、最小备份时间、最大备份数量。
- **自动备份** —— 在游戏退出后按你设的条件执行（默认：一局玩满 20 分钟才备份，
  最多保留 20 份）。
- **更新检查** —— 帮你把游戏版本下下来。走 GitHub 慢的话，去设置里填一个镜像。
  下载中途断了不用从头再来 —— 下次接着已经下好的部分继续。
- **启动预热** —— 窗口一打开就在后台把选中版本的游戏文件拼好，点启动时更快。
- **命令行直接启动** —— 在控制台里敲 `--launch "Mindustry v146"` 就直奔那个版本，
  **全程不出现启动器窗口**；`--list` 列版本、`--help` 看用法（见下节）。
- **命令行导出** —— `--export` 把某个版本拼成一个能直接 `java -jar` 的 jar，
  `--export-backup` 把某个存档备份拼成一个 zip；`--list-backups` 看有哪些备份。
- **命令行改设置** —— `--get` 看当前设置，`--set 键=值` 直接改（下次启动生效）；
  启动器开着时会拒绝，免得被它退出时那次保存盖掉。
- **日志查看** —— 把游戏输出捕获下来，退出后还能看。

## 从命令行直接启动某个版本

在控制台里（cmd、PowerShell、Windows 终端都行）给 exe 加一个参数，就直接进那个版本，
**全程不出现启动器窗口** —— 屏幕上只会看到游戏：

```
"Mindustry启动器.exe" --launch "Mindustry v146"
```

- 版本名就是主界面列表里显示的那一行（`Mindustry v146`、`BE v146` 这样）；
  也可以只写版本号（`v146`）—— 前提是它只属于一个类型，撞名时会告诉你要写全名。
- 记不清版本名？先列一下：

  ```
  "Mindustry启动器.exe" --list
  ```

  它把本机已有的版本一行一个打出来（不启动任何东西）。忘了参数怎么写就敲
  `--help`：用法、退出码、几个注意点都在里面。这两个也**不建窗口** ——
  它们连界面模块都不加载。
- 九个参数**一次只做一件事**，优先级：
  `--help` → `--list` → `--list-backups` → `--get` → `--set` → `--export`
  → `--export-backup` → `--launch`（只读的排前面；导出排在启动前 —— 它不改状态，
  而启动会占住存档目录）。
- 进度和结果都写在**你敲命令的那个控制台**里：正在启动哪个版本、起来了（带本次耗时）、
  游戏退出（带玩了多久）、这一局有没有自动备份。
- 游戏退出后它**自己就结束了**，不用管设置里那个「游戏退出后自动关闭启动器」——
  这种形态既没有窗口也没有托盘图标，留着它没人关得掉。退出前的自动备份照常按
  当时分类的设置执行。
- 跑完时，控制台**最后一行**是 `启动器已退出（退出码 N）` —— **这行就是「结束了」
  的信号**（cmd 对窗口程序**不等待**：命令敲下去，提示符立刻就回来了，还会排在
  程序输出的**前面**；所以结束时不会冒出新的提示符，以这行为准）。想要「命令跑完
  才回到提示符」的手感：把命令放进 `.bat` 里跑（脚本模式下 cmd 会等），或在命令
  前加 `start /wait`。
- 名字写错、或者参数只写了一半（`--launch` 后面没跟名字）时，**什么都不会启动**：
  控制台里说清楚原因（写错时把可用的版本列出来），屏幕上不会多出任何窗口。
- 退出码有意义，脚本里可以直接判断：`0` 正常（游戏玩完退出也算 0）、`1` 启动器崩了、
  `2` 参数写坏、`3` 没有这个版本或这个备份、`4` 版本找到了但没拉起来、
  `5` 导出失败（拼 jar / zip 时出错）、`6` 改配置失败（启动器正开着 / 写不进去）。
  `--launch=<版本>` 这种写法也认；回车的那个控制台会被原样用上。

★ 也可以给快捷方式加这个参数（双击即进游戏）。那种情况没有控制台可写，所以出问题时
会退回成弹窗提示 —— 在控制台里敲，提示就都在控制台里。

## 把版本 / 存档导出成文件

两件事都在命令行里做，都**不启动游戏、不弹启动器窗口**：

```
:: 把一个游戏版本拼成 jar —— 拿到别的机器上能直接 java -jar
"Mindustry启动器.exe" --export "Mindustry v146"

:: 把一个存档备份拼成 zip —— 省略时间戳 = 该分类最新那个
"Mindustry启动器.exe" --export-backup 默认
"Mindustry启动器.exe" --export-backup 默认 2026-09-20_16-35-32
```

- 不记得备份都有哪些？先列一下：
  ```
  "Mindustry启动器.exe" --list-backups
  ```
  它按分类分组，一行一个「时间戳 + 备注」。时间戳就是 `--export-backup` 要填的那个值
  （省掉它 = 该分类最新的那个）。
- 文件默认写到**当前目录**，名字是 `类型_版本号.jar` / `分类_时间戳.zip`。想放到别处
  就加 `--out`（可以是一个文件路径，也可以是一个**已存在的目录**）：
  ```
  "Mindustry启动器.exe" --export "Mindustry v146" --out D:\分享\
  ```
- **同名文件不会被覆盖**：已经有一个同名的，会自动变成 `..._2.jar`、`..._3.jar`。
- 导出的 jar 里保留着原版的 `Main-Class`，所以拿到就能 `java -jar`；导出的 zip 解压
  出来就是存档目录里的内容（可以直接拷进去用）。
- 导出的 jar **是压缩过的**：同一个版本约 120 MB → 87 MB，拼的时候多等几秒；
  不影响 `java -jar`（游戏照常读）。存档 zip 本来也是压缩的。
- 导出是**只读**的：不碰你当前的存档，也不改任何设置 —— 会写存档目录的是「恢复备份」，
  不是它。

## 在控制台里改设置

界面里能改的东西，控制台里也能改 —— 适合写进脚本，或者干脆不想开界面的时候：

```
:: 看全部设置（一行一项：键 = 当前值 # 说明；还是默认值的会标出来）
"Mindustry启动器.exe" --get

:: 只看一项
"Mindustry启动器.exe" --get language

:: 改一项或几项（一次读、一次写；任何一项写错就整批不改）
"Mindustry启动器.exe" --set max_log_files=10
"Mindustry启动器.exe" --set language=en_US auto_update=false
```

- `--get` 打出来的写法可以**直接抄**给 `--set`：`hide_on_launch`、`jvm.jre_path`、
  `profile.默认.max_backups`。分类名换成你自己的（就是设置页里那些）。
- 值写错会**报错**，不会悄悄按默认值存下去：整数有范围（测速轮数 1~3、日志 1~200、
  最小备份时间 1~60、最大备份数量 1~50），语言只认 `auto` / `zh_CN` / `en_US`，
  镜像要像个地址（留空 = 直连）。**任何一项写错，整批都不改** —— 不会"改了一半"。
- **启动器正开着的时候会被拒绝**（退出码 `6`）：它退出时会用内存里的旧配置整个写回，
  这次改动会被盖掉 —— 先关掉启动器再改。界面里的「保存并返回」没有这个问题。
- 改完**下次启动才生效**（语言、镜像、JVM 参数都是启动时读一次的）。
- 带空格的整段参数要用引号包住（否则 cmd 会把它拆成两个参数，第二个会被当成"不是
  键=值"而报错）：
  ```
  "Mindustry启动器.exe" --set "extra_vm_args=-Xmx4G -XX:+UseZGC"
  ```
- 不是所有东西都开放命令行：`version_sources`、`github_mirror_presets` 是数组，
  `profile.<分类>.data_dir` 改了**不会搬文件**（最容易误解），这几项请直接改
  `config.json` 或者用界面。

## 数据放在哪

全部在 exe 旁边，整个文件夹拷走就能一起带走：

```
versions\       下载的游戏版本（自动去重）
Backups\        存档备份
logs\           游戏输出日志（每次启动一份；可在设置里关掉）
extensions\     自己写的扩展（可选，见下节；没有这个目录也不影响）
lang\           自己覆盖的界面文案（可选，见下节）
config.json     你的设置
launcher.log    启动器自己的运行日志 —— 出问题时先看这个
```

## 值得知道的几个设置

- **界面语言** —— `跟随系统`（默认）、`简体中文`、`English`。改完整个界面立刻换过来，
  不用重启。
- **启动器更新** —— `自动`（默认）会在后台悄悄下好，等你关掉启动器时换上；
  `只提示` 只告诉你有新版；`停用` 完全关掉。
- **Java 路径** —— 填 JRE 或 JDK 的根目录即可，也可以直接放一个 `jre\` 文件夹到 exe 旁边。
  填错不用怕：会退回内置那份；连内置的都没有时，还会去 `JAVA_HOME` / `PATH` 里找。
- **GitHub 镜像** —— 留空 = 直连 GitHub。旁边有「测速」：对每个候选
  （含直连）真下一小段、按速度排个序（测的时候有进度条，看得出正在测哪个、
  不用干等），「用最快的」一键填回设置 —— 网速因运营商/地区而异，
  下拉框里的顺序不代表你这里的速度。
- **测速轮数** —— 1~3（默认 3）。每轮把每个候选各测一次，轮数越多排名越稳、
  等待越久（候选数 × 轮数 = 总采样次数）；嫌慢就调到 2 或 1。改完直接点
  「测速」就生效，不必先保存；填 1~3 之外的值会当场提示，不会按别的值跑。
- **使用 GitHub CLI 认证** —— 默认关闭。本机装了 GitHub CLI（`gh`）并
  登录过的话，勾上它，GitHub 请求就带上认证：API 额度从 60 次/时
  （按出口 IP 共享，内网里大家一起分）提高到 5000 次/时。令牌只放在
  内存里、不写入文件；镜像站和自定义来源收不到它。
- **删除文件时直接彻底删除** —— 默认关闭，所以删除走**回收站**、反悔了能还原；
  打开之后就真找不回来了。

⚠️ 改完要点右下角的「保存并返回」才会生效。

## 不用重新打包就能改的东西

下面几项都是往 exe 旁边加点东西、或者手改 `config.json`，改完重启启动器即可 ——
不用重新打包，也不用会编程。

- **界面文字 / 加一门语言** —— 在 exe 旁边新建 `lang\` 文件夹，放一份与程序内置
  **同名**的 JSON（`zh_CN.json` / `en_US.json`），**外面那份优先**。想改词、想加一门
  新语言都走这条路。改坏了最坏情况是某几句显示成设置项的名字（比如
  `settings.save_return`），不会让启动器打不开；删掉外面那份就恢复原样。
- **多加几个「从哪儿下游戏版本」的来源** —— 来源是一张表（`config.json` 的
  `version_sources` 数组），程序内置两个，你可以往里加；`type` 跟内置的重名就是
  **覆盖**它（比如把内置 Mindustry 换成你自己的镜像仓库）。不改代码、不用重新打包。
  字段含义见 `launcher/sources.py`。内置那两个长这样，照这个格式写就行：

  ```json
  "version_sources": [
    { "type": "MindustryX",  "api_url": "https://api.github.com/repos/TinyLake/MindustryX/releases",
      "asset_pattern": "Desktop\\.jar$", "prerelease": false, "sort_rank": 0 },
    { "type": "Mindustry",   "api_url": "https://api.github.com/repos/Anuken/Mindustry/releases",
      "asset_pattern": "Mindustry.jar", "prerelease": null, "sort_rank": 1 }
  ]
  ```

  只有 `type` 和 `api_url` 是必填的；`asset_pattern`（正则，挑哪个文件）、
  `prerelease`（`true`/`false`/`null`＝正式版和预发布都要）、`use_mirror`
  （`false`＝这个来源不走镜像）、`sort_rank`（小号排在前面）都可不写。
  写坏了不会让配置失效 —— 那一项会被丢掉并记一条日志。

- **镜像下拉框里那几个候选** —— `config.json` 的 `github_mirror_presets` 数组，
  写进去就会出现在设置页「GitHub 镜像」的下拉框里。
- **自己加一点功能** —— 在数据根下建 `extensions\` 目录，往里放 `.py`（每个文件里要有
  `register(api)`），启动时自动载入。四个钩子：`on_config_loaded` /
  `on_versions_refreshed` / `on_before_launch` / `on_game_exited`。

  ```python
  # extensions\我的统计.py
  def register(api):
      api.on("on_game_exited", lambda **kw: print(kw["version_name"], kw["playtime_minutes"]))
  ```

  ⚠️ 扩展里的代码跟启动器**同权限**运行，只放自己写的或信得过的文件。
  怀疑是扩展搞的鬼时，设环境变量 `MDT_NO_EXTENSIONS=1` 就全部停用。

⚠️ 手改 `config.json` 之前先**关掉启动器** —— 它退出时会把整个文件重新写一遍，
你开着它改的内容会被冲掉。改坏了不用怕：认不出的键原样保留、写坏的值退回默认
并在 `launcher.log` 里记一条，不会让配置整个作废。

## 注意

- **杀毒软件可能误报**（PyInstaller 打包的 exe 挺常见），信任一下即可。
- 升级启动器**只替换程序文件**（exe 与 `_internal\`），不会动你的游戏版本、存档备份、
  设置、扩展，也不碰 `jre\`。
- 「检查更新」一直失败，多半是连不上 GitHub。可以设一个环境变量 `MDT_SELFUPDATE_API`，
  把它指向你能用起来的代理地址。
- 出问题时把 `launcher.log` 一起发出来，启动器每一步做了什么它都记着。

## Mindustry 本体

本程序不修改、也不重新分发游戏本体 —— 它只是从官方发布页下载可执行文件，
然后启动一个独立进程。
