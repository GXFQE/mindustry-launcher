# Mindustry 启动器 —— Windows 上的多版本管理器

> **找的是安卓版？** 那是另一个项目 → **[MDT 管理器（Android）](https://github.com/GXFQE/mindustry-launcher-android)**。

官方的 Mindustry（像素工厂）桌面版只给 jar：想留几个版本，得自己建目录、记住哪个文件是哪个，
每次手敲 `java -jar`。更麻烦的是**所有版本共用一份数据** —— `%APPDATA%\Mindustry` 里的
存档 / 地图 / 蓝图 / 模组 / 设置，在哪个版本里玩都压在同一个地方。

这个启动器把这两件事拆开：版本并排留着、点一下就启动；每个**存档分类**是一整套独立的数据目录；
退出后按条件自动备份。**Java 已经打包在里面**，不用装 Python，也不用单独装 Java。

## 它解决什么

| 自己管 jar + 官方数据目录 | 用这个启动器 |
|---|---|
| 几个版本并存要自己建目录、记哪个 jar 是哪个，每次手敲 `java -jar` | 版本列表一行一个，选中点「启动游戏」；窗口一打开就在后台把文件拼好，点下去不用等 |
| 所有版本共用 `%APPDATA%\Mindustry`，切版本 = 把旧进度顶掉 | **存档分类**：一个分类一整套数据目录，启动前切一下，互不覆盖 |
| 多留一个版本就多占一整套体积（约 110 MB） | 版本文件按内容拆开、**相同的只存一份**，只多出真正不同的部分 |
| 备份靠自己整个复制一遍，过几天分不清哪份是哪份 | 退出后**自动备份**（默认玩满 20 分钟、留 20 份），可加备注、可一键恢复 |
| 更新得去 GitHub 翻 release、挑文件，网络一抖就断 | 「检查更新」走一张**来源表**，带镜像、测速和**断点续传** |
| 机器上得先有 Java，版本不对还起不来 | **内置 JRE**；也能用自己那份 JDK，逐层兜底 |
| 出了问题只有游戏那份日志，还写在 `%APPDATA%` 里 | 游戏输出被捕获下来，按分类留一份，日志窗口里直接看 |
| 想从脚本、批处理或快捷方式直接进游戏，总得先开启动器 | `--launch "版本名"` **零界面**直进 |

**它是怎么做到的**：把每个版本拆成许多小文件块存起来（相同的块只留一份），启动前拼成运行时 jar；
存档隔离靠启动时把游戏的**数据目录**指向那个分类。游戏本体、存档格式、模组生态都没被改动。

## 怎么用

1. **下载** —— 从 [Releases](../../releases/latest) 拿发布包，解压到**有写权限**的位置
   （别放 `C:\Program Files`、桌面），双击 `Mindustry启动器.exe`。
2. **先把一个版本弄进来** —— 点「**检查更新**」下载一个（走 GitHub，慢就设镜像）；
   或「**管理版本 → 导入版本**」选别人给的 `desktop.jar`，填一下类型和版本号。
3. **开玩** —— 列表里选中它，点「**启动游戏**」。想再要一套独立存档：主界面「**管理存档**」
   新建分类 → 切过去 → 再启动。

界面**跟随系统语言**（中文 / 英文），设置里可以覆盖。包内 `使用说明.txt` 是步骤版，中英对照。

## 能做什么

### 版本

- 一行一个版本（`Mindustry v146` 这样），选中点「启动游戏」；「管理版本」里导入、重命名、删除
- **相同文件只存一份**，多装一个版本不会多占一整套
- **启动预热**：窗口一打开就在后台拼好运行时 jar，点下去不用等

### 存档分类

- 一个分类 = 一整套数据目录：存档 / 地图 / 蓝图 / 模组 / 设置，主界面顶部切换
- 每个分类单独设：数据目录、自动备份开关、最小备份时间、最大备份数量
- ⚠️ 改数据目录只改「以后用哪个」，原有存档不会被搬走；游戏在跑时不让切

### 备份与恢复

- 退出后按条件自动备份，也能「立即备份」；备份带备注，可一键恢复
- 备份按内容去重，多留几份不成倍占地方；超出份数从最旧的开始删
- 删除走**回收站**（设置里可以改成彻底删除）

### 更新与镜像

- 「从哪儿下版本」是一张表：内置 Mindustry / MindustryX，`version_sources` 可加、可覆盖
- 镜像留空 = 直连；「测速」对每个候选真下一小段并一键填回；断了下次接着下
- 下完核对大小 / 校验值再装进版本库

### 命令行

- 十七个开关：启动、列版本、列备份、查更新、看 / 改设置、导出 jar、导出存档 zip、
  导入 jar、恢复备份、删版本 / 删备份 —— 零界面、有退出码，适合脚本和快捷方式。
  删版本 / 删备份 / 恢复备份必须带 `--yes`，而且启动器得是关着的
- 完整开关表、退出码、命令行改设置的边界，见 **[详细用法](docs/USAGE.zh_CN.md#命令行)**

### 日志

- 游戏输出实时显示、退出后还能看，`logs\` 里每次一份；启动器自己的日志是 `launcher.log`

## 现在还没有的

- **macOS / Linux**：只发布 Windows 版（exe + 随包的 Windows JRE）
- **命令行没有 `--version`**，`--launch` 也不能临时换一个存档分类
- **删除存档分类故意只给界面**：它要经过三重确认，数据目录走回收站。版本和单条备份
  可以在命令行删（`--delete-version`、`--delete-backup`），备份也能用 `--restore-backup`
  放回去 —— 这三个都要带 `--yes`
- **模组 / 地图 / 蓝图没有专门界面**：隔离按整个数据目录做，这三样跟着分类走，但列表、
  导入导出、缺件分析留给游戏

## 不打算做的

- **打包或重新分发游戏本体**：版权归各自作者，版本一律从官方发布页（或你指定的来源）下载
- **改游戏本体**：不注入、不打补丁、不改动游戏内容；只把官方文件原样拼成能运行的 jar 再启动
- **多线程下载**：单线程够用，力气花在断点续传和换源上更值
