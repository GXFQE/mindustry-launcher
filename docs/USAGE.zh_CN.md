# 详细用法 —— Mindustry 启动器

面向已经跑起来、想知道细节的人。**程序是做什么的、怎么开始**，看 [README.zh_CN.md](../README.zh_CN.md)。

## 命令行

界面能做的大部分事，命令行里也有对应的一份 —— 适合写进脚本、快捷方式，或者干脆不想开界面。
（导入 jar、恢复备份、重命名版本只能在界面里做；删除存档分类**故意**不给命令行 —— 它要经过
三重确认。）

| 开关 | 做什么 |
|---|---|
| （不加参数） | 打开启动器界面 |
| `--launch <版本>` | 直接启动某个版本，**全程不显示启动器窗口**；游戏退出后启动器自己收工 |
| `--list` | 列出本机已有版本（不启动任何东西，连界面模块都不加载） |
| `--list-backups` | 按分类列出存档备份（时间戳 + 备注） |
| `--get [键]` | 看设置；不写键就全列出来（一行一项：键 = 值 # 说明，还是默认值的会标出来） |
| `--set 键=值 …` | 改设置（只写 `config.json`，下次启动生效；能一次给好几项） |
| `--export <版本>` | 把版本拼成能直接 `java -jar` 的 jar，可加 `--out` |
| `--export-backup <分类> [时间戳]` | 把一份备份拼成 zip（省略时间戳 = 最新那个），可加 `--out` |
| `--delete-version <版本>` | 删掉一个版本（清单 + 随后回收没人引用的对象）。**必须带 `--yes`** |
| `--delete-backup <分类> [时间戳]` | 删掉一份备份（省略时间戳 = 最新那个）。**必须带 `--yes`** |
| `--yes` | 确认删除。少了它，删除一个字节都不动 |
| `--help` | 用法、退出码、几个注意点 |

```bat
:: 直接进游戏（屏幕上只有游戏，没有启动器）
"Mindustry启动器.exe" --launch "Mindustry v146"

:: 把版本拼成 jar 带走 —— 不给 --out 就写到当前目录
"Mindustry启动器.exe" --export "Mindustry v146" --out D:\分享\

:: 改两项设置，下次启动生效
"Mindustry启动器.exe" --set language=en_US auto_update=false
```

### 几条必须知道的

- **一次只做一件事**，优先级：`--help` → `--list` → `--list-backups` → `--get` → `--set`
  → `--export` → `--export-backup` → `--delete-version` / `--delete-backup` → `--launch`
  （只读的排前面；导出排在启动前 —— 它不改状态，而启动会占住存档目录；删除排在导出后，
  于是 `--export-backup X --delete-backup X` 天然是「先留副本、再删」）。
- **版本名**就是主界面列表里那一行（`Mindustry v146`、`BE v146`）；也可以只写版本号（`v146`），
  前提是它只属于一个类型，撞名时会告诉你要写全名。名字写错、或者 `--launch` 后面没跟名字，
  **什么都不会启动**，控制台里把可用版本列出来。
- **零界面**：进度和结果都写在**你敲命令的那个控制台**里 —— 正在启动哪个版本、起来了（带本次耗时）、
  游戏退出（带玩了多久）、这一局有没有自动备份。
- ⚠️ **cmd 对窗口程序不等待**：命令敲下去，提示符立刻就回来，还排在程序输出**前面**。所以以
  **最后一行** `启动器已退出（退出码 N）` 为准。想要「跑完才回到提示符」的手感，把命令放进
  `.bat`（脚本模式下 cmd 会等），或者前面加 `start /wait`。
- 给快捷方式加参数也能用（双击即进游戏）。那种情况没有控制台可写，出问题会退回成弹窗提示。
- **导出不覆盖**：同名文件已存在时自动变成 `..._2.jar`、`..._3.jar`。导出的 jar 是压缩过的
  （同一个版本约 120 MB → 87 MB，拼的时候多等几秒），保留原版 `Main-Class`，拿到就能
  `java -jar`；导出的 zip 解压出来就是存档目录里的内容。
- **导出是只读的**：不碰你当前的存档，也不改任何设置 —— 会写存档目录的是「恢复备份」。

### 退出码（脚本里 `%ERRORLEVEL%` 能拿到）

| 码 | 含义 |
|---|---|
| `0` | 正常结束（包括游戏玩完退出） |
| `1` | 启动器自己出错 |
| `2` | 参数写坏了（`--launch` 后面没写版本名、`--set` 后面没写 `键=值`、删除没带 `--yes`） |
| `3` | 没有这个版本 / 没有这个备份 |
| `4` | 版本找到了，但游戏没起来 |
| `5` | 导出失败（拼 jar / zip 时出错） |
| `6` | 改配置失败（启动器正开着 / 写不进去 / 回读对不上） |
| `7` | 删除失败（清单删不掉、删完回读发现它还在，或者启动器正开着） |

### 删掉一个版本 / 一份备份

删除是这里唯一不可逆的动作，所以上了两道闸：必须显式 `--yes`，而且启动器必须是关着的。

```bat
:: 删掉一个版本（随后回收没人引用的对象）
"Mindustry启动器.exe" --delete-version "Mindustry v146" --yes

:: 删掉某个分类最新那份备份
"Mindustry启动器.exe" --delete-backup 默认 --yes

:: 删掉指定的一份（时间戳从 --list-backups 里抄）
"Mindustry启动器.exe" --delete-backup 默认 2026-09-20_16-35-32 --yes
```

- **不带 `--yes` 什么都不做** —— 退出码 `2`，一个文件都不碰。命令行是给脚本跑的，
  没法在那里问一句「你确定吗」。
- **只删清单，不动存档**。数据对象放在共享池里，只有在没人引用之后（别的备份、别的分类）
  才会被回收。
- **启动器正开着时会被拒绝**（退出码 `6`）：它内存里的版本 / 备份列表还指着要删的东西。
  关掉再跑一次。
- 回收那一趟要扫完整个对象池（本项目 3 万+ 个对象，一般十几秒），所以删除明显比列清单慢。
- 备份只认**磁盘上真的存在**的分类名和时间戳：分类名是拿去查表的，从不拼进路径，
  所以 `..` 逃不出备份目录。

### 用 `--set` 改设置

- `--get` 打出来的写法可以**直接抄**给 `--set`：`hide_on_launch`、`jvm.jre_path`、
  `profile.默认.max_backups`。分类名换成你自己的。
- 值写错会**报错**，不会悄悄按默认值存下去；**任何一项写错，整批都不改**。
- 数值范围跟设置页的数字框一致 —— 最小备份时间 1~60、最大备份数量 1~50、测速轮数 1~3、
  日志保留份数 1~200；语言只认 `auto` / `zh_CN` / `en_US`；镜像要像个地址（留空 = 直连）。
  超范围直接报错，**不夹取**。
- **启动器正开着的时候会被拒绝**（退出码 `6`）：它退出时会用内存里的旧配置整个写回，
  这次改动会被盖掉 —— 先关掉再改。界面里的「保存并返回」没有这个问题。
- 带空格的整段参数要用英文双引号包住（否则 cmd 会把它拆成两个参数）：

  ```bat
  "Mindustry启动器.exe" --set "extra_vm_args=-Xmx4G -XX:+UseZGC"
  ```

- **不是所有东西都开放**：`version_sources`、`github_mirror_presets` 是数组，
  `profile.<分类>.data_dir` 改了**不会搬文件**，`jvm.main_class` / `jvm.vm_args` 改错了是
  「游戏起不来」—— 这几项请手改 `config.json` 或用界面（VM 参数走 `extra_vm_args`）。

## Java 与启动参数

- 双击就能跑：`jre\` 已经随包带上。
- **Java 路径**填 JRE 或 JDK 的**根目录**（里面要有 `bin\java.exe`）；只写 `jre` 表示 exe 旁边
  那个；旁边有「检测」按钮可以找一个。
- 兜底顺序：设置里填的 → 旁边的 `jre\` → 系统 `JAVA_HOME` / `PATH` → 都没有才报错。
  ⚠️ 找到的系统 Java **只用于这一次**，不会悄悄写进设置。
- **额外 JVM 参数**加在 `-cp` 之前（如 `-Xmx4G`）；**额外游戏参数**加在主类之后，一般用不到。
- 含空格的整项用英文双引号包住：`-Dfoo="bar baz"`。路径里的反斜杠（`C:\...`）原样写，不用转义。

## 日志

- 游戏输出实时显示，退出后还能看；`logs\` 里每次启动留一份（设置里可以关掉）。
- 日志窗口分段：**游戏输出** / **启动器日志**；能复制、能打开所在文件夹。
- 保留份数 1~200（默认 20），超出从最旧的开始丢，下次启动游戏生效。
- 启动器自己的运行日志是 `launcher.log` —— 出问题先看这个。
- 游戏自己那份 `last_log.txt` 写死在 `%APPDATA%\Mindustry`，换了分类也拿不到；启动器会在退出后
  把它抄进当前分类的日志里。

## 数据放在哪

全部在 exe 旁边，整个文件夹拷走就能一起带走：

```
versions\       游戏版本（相同文件只存一份）
Backups\        存档备份（按分类存放，同样去重）
logs\           游戏输出日志（每次启动一份）
runtime\        游戏进程的工作目录（游戏自己往里写缓存，不用管）
extensions\     自己写的扩展（可选，没有这个目录也不影响）
lang\           自己覆盖的界面文案（可选）
config.json     你的设置
launcher.log    启动器自己的运行日志
```

## 设置逐项

**每个存档分类各自一份**（设置页上半部分）：

| 设置 | 说明 |
|---|---|
| 分类名称 | 就是「默认」这些名字，改名不会搬目录 |
| 数据目录 | 这个分类读写的游戏数据目录。改它**只改「以后用哪个」**，原有存档不会被搬走 |
| 最小备份时间 | 1~60 分钟：一局玩不够这么久就跳过不备份 |
| 最大备份数量 | 1~50 份：超出后自动删最旧的 |
| 启用自动备份 | 关掉就只有「立即备份」 |

**启动器设置**（所有分类共用）：

- **界面语言** —— `跟随系统`（默认）、`简体中文`、`English`；改完整个界面立刻换过来。
- **启动器更新** —— `自动`（默认）后台悄悄下好、关掉时换上；`只提示` 只告诉你有新版；
  `停用` 完全关掉。只替换程序文件，不动版本、配置、备份和存档；源码运行时自动停用。
- **GitHub 镜像** —— 下载 jar 时拼在地址前做加速；留空 = 直连，这个源拉不动会自动换下一个。
- **测速 / 测速轮数** —— 1~3（默认 3）。每轮把每个候选各测一次，轮数越多排名越稳、等得越久；
  填 1~3 之外的值会当场提示，不按别的值跑。
- **使用 GitHub CLI 认证** —— 默认关闭。本机装了 `gh` 并登录过的话勾上：API 额度从 60 次/时
  （按出口 IP 共享）提到 5000 次/时。令牌只放内存、不写文件，镜像站和自定义来源收不到它。
- **额外 JVM 参数 / 额外游戏参数** —— 见上面「Java 与启动参数」。
- **日志保留份数** —— 1~200。
- **删除文件时直接彻底删除** —— 默认关闭，所以删除走回收站、反悔了能还原；打开之后真找不回来。
  只作用于存档目录、旧日志这类用户文件。
- **启动时隐藏窗口 / 游戏退出后自动关闭** —— 想要「点一下只剩游戏」的观感就开这两个
  （自动关闭会等备份做完）。

⚠️ 改完要点「保存并返回」才会生效 —— 设置页只有这一个出口，校验没过会留在本页。

## 不用重新打包就能改的东西

往 exe 旁边加点东西、或者手改 `config.json`，重启即可 —— 不用重新打包，也不用会编程。

### 界面文字 / 加一门语言

新建 `lang\` 文件夹，放一份与内置**同名**的 JSON（`zh_CN.json` / `en_US.json`），**外面那份优先**。
改坏了最坏是某几句显示成键名（比如 `settings.save_return`），删掉外面那份就恢复原样。

### 多加几个「从哪儿下版本」的来源

来源是一张表（`config.json` 的 `version_sources` 数组），程序内置两个，你可以往里加；
`type` 跟内置的重名就是**覆盖**它（比如把内置 Mindustry 换成你自己的镜像仓库）。内置那两个长这样：

```json
"version_sources": [
  { "type": "MindustryX",  "api_url": "https://api.github.com/repos/TinyLake/MindustryX/releases",
    "asset_pattern": "Desktop\\.jar$", "prerelease": false, "sort_rank": 0 },
  { "type": "Mindustry",   "api_url": "https://api.github.com/repos/Anuken/Mindustry/releases",
    "asset_pattern": "Mindustry.jar", "prerelease": null, "sort_rank": 1 }
]
```

只有 `type` 和 `api_url` 是必填的；`asset_pattern`（正则，挑哪个文件）、`prerelease`
（`true` / `false` / `null` = 正式版和预发布都要）、`use_mirror`（`false` = 这个来源不走镜像）、
`sort_rank`（小号排在前面）都可不写。写坏了不会让配置失效 —— 那一项会被丢掉并记一条日志。
字段含义见 `launcher/sources.py`。

### 镜像下拉框里的候选

`config.json` 的 `github_mirror_presets` 数组，写进去就会出现在设置页「GitHub 镜像」的下拉框里。

### 自己加一点功能（扩展）

在数据根下建 `extensions\` 目录，往里放 `.py`（每个文件里要有 `register(api)`），启动时自动载入。
四个钩子：`on_config_loaded` / `on_versions_refreshed` / `on_before_launch` / `on_game_exited`。

```python
# extensions\我的统计.py
def register(api):
    api.on("on_game_exited", lambda **kw: print(kw["version_name"], kw["playtime_minutes"]))
```

⚠️ 扩展里的代码跟启动器**同权限**运行，只放自己写的或信得过的文件。怀疑是扩展搞的鬼时，
设环境变量 `MDT_NO_EXTENSIONS=1` 就全部停用。

## 出问题时

- **杀毒软件可能误报**（PyInstaller 打包的 exe 挺常见），信任一下即可。
- 升级启动器**只替换程序文件**（exe 与 `_internal\`），不碰游戏版本、备份、设置、扩展，也不动 `jre\`。
- 「检查更新」一直失败，多半是连不上 GitHub：换镜像，或者设环境变量 `MDT_SELFUPDATE_API`
  指向你能用起来的代理。
- 手改 `config.json` 之前先**关掉启动器** —— 它退出时会把整个文件重写一遍。改坏了不用怕：
  认不出的键原样保留、写坏的值退回默认并在 `launcher.log` 里点名是哪个键。
- 要报问题时，把 `launcher.log`（必要时加上 `logs\` 里的游戏输出）一起发出来 —— 每一步它都记着。
